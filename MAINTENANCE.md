# Журнал сопровождения

## 2026-09-09 — устаревшее число игр в README и молчаливая потеря игры при сборке

**Что исправлено**

- `README.md`: строка `src/js/games/*.js` в разделе «Структура репозитория»
  говорила «шесть игр» — на деле в каталоге уже десять файлов (`arkanoid.js`,
  `snake.js`, `moto.js`, `moto3d.js`, `cars3d.js`, `duel3d.js`, `planes.js`,
  `tanks.js`, `contra.js`, `sonic.js`, что совпадает с таблицей игр в начале
  README и с массивом `GAMES` в `src/content.js`). Заменено на «десять игр».
- `build.js`: перед сборкой сверяет список файлов в `src/js/games/` со
  списком `SCRIPTS` из `src/content.js` и падает с понятным сообщением,
  если файл есть, а в `SCRIPTS` не подключён.

**Зачем**

Число в README разошлось с кодом после трёх коммитов, добавивших
Самолётики, Танчики/Десант/Ёжика (`1b85699`, `206d7f3`) — строку про
структуру каталога никто не обновил. Раздел «Как добавить игру» в том же
README перечисляет шаг «положить файл в `src/js/games/`» отдельно от шага
«добавить путь в `SCRIPTS`» — если второй шаг пропустить, `node build.js`
сейчас отработает молча и просто не создаст страницу для новой игры: файл
не читается, ошибки нет, а `SCRIPTS`, наоборот, крашит сборку сразу, если
путь в нём битый (`fs.readFileSync` бросает ENOENT). То есть одна половина
рассинхронизации уже была защищена, а другая — нет. Добавленная проверка
ловит именно вторую половину, до того как автор заметит на сайте
недостающую игру.

**Совместимость**

Проверка ничего не запрещает из того, что раньше работало: прогнал
`node build.js` на текущем состоянии репозитория — сайт собрался как
раньше (все 19 HTML-страниц, sitemap, dist-бандл), новая проверка молча
прошла, потому что все десять игр уже перечислены в `SCRIPTS`. Отдельно
проверил, что проверка действительно падает: скопировал существующий файл
игры под новым именем в `src/js/games/`, не регистрируя его — сборка
завершилась с кодом выхода 1 и понятным сообщением, тестовый файл удалён.
`docs/` (результат сборки, отдаётся GitHub Pages) не трогал — локальный
прогон `build.js` проставляет сегодняшнюю дату и обнуляет `leaderboard.json`
(тот отдельно обновляется workflow `leaderboard.yml`), так что коммитить
такой локальный ребилд `docs/` было бы регрессией; менялись только
`README.md` и `build.js`.
